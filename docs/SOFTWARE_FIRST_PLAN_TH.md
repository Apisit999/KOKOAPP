# แผน: ทำตัวโปรแกรมให้ใช้งานได้จริงก่อน (รอกล้องและเครื่องพิมพ์)

บันทึกวันที่ 30 ตุลาคม 2026 · เจ้าของโปรเจคเป็นผู้กำหนดทิศทางนี้

## ข้อตกลง

1. **ตอนนี้ยังไม่มีกล้องและเครื่องพิมพ์จริง** เจ้าของจะหามาทีหลัง ห้ามอ้างว่า "รองรับ" หรือ "ทดสอบแล้ว" กับฮาร์ดแวร์ใดจนกว่าจะมีผลทดสอบจริง (สอดคล้องกับ `CAMERA_COMPATIBILITY_PLAN.md`)
2. **ทำโปรแกรมส่วนที่เหลือให้เสร็จและใช้งานได้จริงก่อน** โดยใช้ webcam, ภาพตัวอย่าง และ Simulate print เป็นตัวแทน
3. **ออกแบบเผื่อฮาร์ดแวร์ไว้ล่วงหน้า** ให้ตอนได้เครื่องมาแล้วเสียบเพิ่มได้โดยไม่ต้องรื้อโครงสร้าง (ดู "จุดเผื่อฮาร์ดแวร์")
4. ช่วง Free pilot แจกจ่ายผ่านเว็บ (ดาวน์โหลด สถิติ เช็กอัปเดต) ตาม `docs/KOKO_STUDIO_FREE_PILOT_DOWNLOAD_UPDATE_PLAN.md` ใน repo เว็บ KOKOMEMORYTES

## สถานะ ณ ตอนนี้ (0.1.28)

ใช้งานได้แล้ว (ผ่านเทสต์อัตโนมัติ 95 ข้อ): ถ่ายจาก webcam, บันทึก JPEG/WebM, เทมเพลตและ editor, คิวพิมพ์แบบทนทานพร้อม Simulate print, import ภาพจาก camera export folder, หน้าจอแขก, อัลบั้มคลาวด์ + QR (ต้องมี license แบบเสียเงิน), Free license ที่เซิร์ฟเวอร์ลงลายเซ็น, เชื่อมบัญชีเว็บ, **เช็กอัปเดตจากเว็บ (เพิ่มใหม่)**

ยังไม่เคยทดสอบ: กล้องจริง, เครื่องพิมพ์จริง, ติดตั้ง/อัปเกรดทับ/ถอนการติดตั้งบน Windows สะอาด, UI ที่แพ็กแล้วครบทุกหน้า (harness ติดปัญหา AppContainer), แบนเนอร์อัปเดตบนหน้าจอจริง

## งานที่ทำได้เลยโดยไม่ต้องมีฮาร์ดแวร์ (ลำดับแนะนำ)

1. **รัน flow ตัวอย่างครบวงจร:** ถ่าย (หรือใช้ภาพตัวอย่าง) → ตรวจ/ถ่ายใหม่ → ประกอบเทมเพลต → ส่งเข้าคิว Simulate print → ปิดแอปแล้วเปิดใหม่ ข้อมูลต้องอยู่ ใช้ webcam ของเครื่องเป็นกล้อง
2. **ทดสอบแอปที่แพ็กแล้วบนเครื่อง Windows สะอาด (หรือ VM):** ติดตั้ง → รับ Free → ใช้งาน → ติดตั้งรุ่นใหม่ทับ → ตรวจรูป เทมเพลต license ยังอยู่ → ถอนการติดตั้ง แก้ปัญหา harness ที่ติด AppContainer
3. **ทดสอบแบนเนอร์อัปเดตจริง** และปรับ UX (บังคับอัปเดต, สำรองข้อมูล) ให้ชัด
4. **คู่มือผู้ใช้และหน้า Help** สำหรับผู้ทดลอง: ติดตั้ง, SmartScreen, รับ Free, ตั้งอีเวนต์, ใช้เทมเพลต, ปัญหาที่พบบ่อย
5. **ความทนทาน:** พื้นที่ดิสก์เต็ม, ปิดเครื่องกลางถ่าย, ไฟล์เสีย, ออฟไลน์ ฝึกตามตาราง `KNOWN_RISKS.md`
6. **ช่องทางรับ feedback และ log:** ปุ่ม "แจ้งปัญหา" ที่แนบเวอร์ชัน/ระบบ (ห้ามแนบ token หรือรูปลูกค้าโดยไม่ถาม)
7. **ปรับรุ่นและเอกสาร:** แยกเลขรุ่น, release notes ภาษาไทย, checksum

## จุดเผื่อฮาร์ดแวร์ (ทำโครงไว้ แต่ยังไม่อ้างว่ารองรับ)

| ส่วน | สถานะในโค้ด | ที่ต้องเตรียมไว้ |
| --- | --- | --- |
| กล้อง | `camera-adapter.ts` ระบุ capability ชัดเจนเป็น `video-input` (webcam/UVC) ยังไม่มี remote shutter | ทำ interface `CameraDescriptor` / `CameraCapabilities` ตาม `CAMERA_COMPATIBILITY_PLAN.md` ให้ webcam เป็น adapter แรก และเพิ่ม **Simulated camera adapter** (ภาพตัวอย่าง) เพื่อทดสอบ flow ไม่ต้องมีกล้อง ห้ามเดารุ่นจากชื่ออุปกรณ์ |
| กล้อง DSLR/Mirrorless | รองรับเฉพาะ import JPEG จาก export folder ของโปรแกรม tethering | ช่อง adapter สำหรับ Canon/Sony แยก helper process ในอนาคต ไม่ต้องลงมือจนกว่าจะรู้รุ่นและมีเครื่องทดสอบ |
| เครื่องพิมพ์ | คิวพิมพ์ + Simulate print มีแล้ว สถานะ `submitted` แปลว่า Windows รับงาน ไม่ยืนยันว่ากระดาษออก | เพิ่มโครง "โปรไฟล์เครื่องพิมพ์" (ขนาดกระดาษ, margin, borderless) และรายการยอมรับต่อรุ่น กรอกเมื่อได้เครื่อง |
| ตัวช่วยตรวจฮาร์ดแวร์ | ยังไม่มี | หน้า "ตรวจความพร้อม" แสดงกล้องที่พบ/สิทธิ์/เครื่องพิมพ์ที่พบ และข้อความแก้ปัญหา ใช้ได้ทั้งกับ webcam วันนี้และอุปกรณ์จริงภายหลัง |
| รายการอุปกรณ์ที่รองรับ | ยังไม่มี | ตาราง "ทดสอบแล้ว / ยังไม่ทดสอบ" ในเว็บและแอป เติมเมื่อมีผลจริงเท่านั้น |

## เมื่อได้ฮาร์ดแวร์มา

1. บันทึกรุ่น/firmware/ไดรเวอร์ลงตารางทดสอบ
2. ทดสอบ webcam/กล้องผ่านเส้นทางที่มี (UVC หรือ folder import) ก่อนเขียน SDK
3. เครื่องพิมพ์: พิมพ์ทดสอบทุกขนาดกระดาษที่ประกาศรองรับ ตรวจขอบ สี ทิศทาง และข้อความเมื่อเครื่องออฟไลน์ แล้วจึงอัปเดตสถานะ "ทดสอบแล้ว"
4. ค่อยตัดสินใจเรื่อง Canon EDSDK/CCAPI หรือ Sony SDK ตามรุ่นที่ได้จริง (ตรวจสิทธิ์ SDK และการแจกจ่ายก่อน)

## ข้อห้าม

- ห้ามเขียนในเอกสารหรือหน้าเว็บว่ารองรับกล้อง/เครื่องพิมพ์รุ่นใดก่อนมีผลทดสอบ
- ห้ามเปิดดาวน์โหลดสาธารณะก่อนผ่าน gate ใน `KOKO_STUDIO_SALES_AND_INSTALLATION_PLAN.md`
