## Exact first implementation milestone after approval

Milestone 1 creates a separate desktop repository in an approved location, pins compatible Electron/React/TypeScript/Vite/Forge versions with a single npm lockfile, sets up the isolated renderer and narrow preload contract, creates a simple polished operator/guest shell, persists nonsecret settings, writes redacted local logs, and produces a Windows installable artifact. It ends after launch, security configuration, packaged smoke test, and touch/keyboard walkthrough. No camera or photo data code is part of it.

## UX delivery gates

M1: visual design tokens, two clear modes, keyboard focus and fullscreen exit. M2: capture screen with large countdown and saved locally confirmation, clear camera/storage indicators. M3: event name always visible and change guarded. M4: template preview matches output. M6: sync statuses distinguish waiting, uploading, needs attention and uploaded. M7: sharing state and audience visible before QR. M8: printer state visible only when enabled. Use event-staff review on a target screen at each gate; decorative polish never obscures error or save state.

## Performance targets to measure, not guarantees

On a declared reference PC and camera: cold startup to operator screen target ≤5 seconds; preview interaction latency target ≤150 ms; capture to safely saved local original target ≤3 seconds for a 12 MP JPEG equivalent; thumbnail visible target ≤2 seconds after save; queue state update target ≤1 second; idle memory target ≤400 MiB; no sustained preview CPU saturation; DB single-record operations target p95 ≤50 ms. Set upload throughput target after staging network baseline. Record p50/p95, file size, OS, hardware and failure rate. Adjust only from measured evidence; do not block capture on thumbnail or upload work. Bound processing and upload concurrency, starting at one and increasing only after measurement.

## Before a real event

Complete a rehearsal on the actual PC, Windows build, camera, cable, storage volume, display and printer if used. Capture at least an event-sized sample, force power/restart and network outages, verify saved originals and queue recovery, verify correct album/QR permissions, check disk reserve and backup, test full-screen escape and operator handoff, and keep a documented offline/export fallback. No website production write or public gallery test without an approved staging-to-production process.
