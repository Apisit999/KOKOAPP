# รายงานตรวจสอบและปิดงาน Milestone 1

วันที่ตรวจสอบ: 30 กันยายน 2026  
โครงการ: `D:\pKOKO`

> **สถานะล่าสุด:** ผู้ใช้ยืนยันผลทดสอบด้วยตนเองบน Windows ผ่านครบทั้ง 9 รายการแล้ว รายละเอียดและขอบเขตการยืนยันอยู่ในหัวข้อ “ผลยืนยันการทดสอบบน Windows ล่าสุด” ท้ายรายงาน ส่วนผลอัตโนมัติระบุแยกต่างหากและไม่ถือเป็นผลทดสอบด้วยตนเอง Installer ยังไม่มีลายเซ็นดิจิทัล

## สรุปผลการดำเนินงาน

ตรวจสอบโค้ด รายงานเดิม การตั้งค่า การทำงานของหน้าต่าง และไฟล์ Build ของ Milestone 1 แล้ว แก้จุดเสี่ยงหนึ่งจุดในลำดับสมัครรับเหตุการณ์อินสแตนซ์ที่สอง และสร้าง Installer ใหม่จากซอร์สปัจจุบันได้สำเร็จ

สถานะก่อนรับผลทดสอบ Windows: ยังรอการยืนยันการใช้งานจริง ข้อมูลนี้ถูกปรับปรุงแล้วตามผลที่ผู้ใช้ยืนยันในหัวข้อท้ายรายงาน

## ผ่านการตรวจสอบ

### ข้อความภาษาไทยและ Build

- อ่าน `src/renderer/main.tsx` และ HTML ด้วย UTF-8 พบอักษรไทย 602 ตัว ไม่พบรูปแบบข้อความเพี้ยนที่ตรวจหา

### Settings, Fullscreen, Escape และวงจรแอป

- `Settings` ปัจจุบันประกอบด้วย `language`, `highContrast` และ `fullscreen`; ไม่พบการตั้งค่าคุณภาพรูปภาพในชนิดข้อมูลหรือหน้าจอ Settings ปัจจุบัน
- Main process ตรวจรูปแบบ Settings ก่อนบันทึก อ่านจาก `userData/settings.json` และเขียนผ่านไฟล์ชั่วคราวก่อนแทนที่ไฟล์จริง
- ค่า Fullscreen ที่บันทึกไว้ถูกนำมาใช้เมื่อสร้างหน้าต่าง; การเปลี่ยนตัวเลือก “เริ่มแอปแบบเต็มหน้าจอ” ระหว่างใช้งานมีผลกับการเริ่มแอปครั้งถัดไป
- การเปิด Guest เรียกคำสั่ง Fullscreen; ปุ่มกลับและปุ่ม Escape กลับสู่ Operator และสั่งออกจาก Fullscreen
- แอปขอ Single-instance lock ระหว่างเริ่มต้น และปิดแอปเมื่อทุกหน้าต่างปิด
- แก้การสมัครรับ `second-instance` ให้เกิดขึ้นก่อน `ready` เพื่อลดช่วงที่อินสแตนซ์ที่สองอาจส่งเหตุการณ์มาก่อนมีตัวรับ
- `npm.cmd run typecheck` ผ่านหลังแก้โค้ด

## ไม่ผ่าน

- `npm.cmd run make` ใน sandbox ล้มเหลวด้วย `TypeError: fetch failed` ที่ขั้น `Copying files`
- `npm.cmd run lint` ใช้งานไม่ได้ เพราะ `package.json` ไม่มีสคริปต์ `lint`; npm แจ้ง `Missing script: "lint"`
- `npm.cmd test` ใช้งานไม่ได้ เพราะ `package.json` ไม่มีสคริปต์ `test`; npm แจ้ง `Missing script: "test"`
- Installer ยังไม่ได้ลงลายเซ็นดิจิทัล

## สาเหตุของข้อผิดพลาดการสร้างแพ็กเกจ

Forge แสดง `TypeError: fetch failed` ระหว่างคัดลอกไฟล์ Electron เมื่อรันใน sandbox แต่คำสั่ง `npm.cmd run make` ที่สร้างซอร์สชุดเดียวกันสำเร็จเมื่อรันนอก sandbox โดยไม่เปลี่ยนโค้ดหรือระบบ Installer หลักฐานนี้แยกปัญหาเป็นข้อจำกัดการดึงไฟล์ผ่านเครือข่ายใน sandbox มากกว่าข้อผิดพลาดในโค้ด

ข้อความ Forge ไม่ระบุ URL หรือชื่อ Dependency ที่ร้องขอ จึงระบุปลายทางเครือข่ายที่ล้มเหลวให้เฉพาะเจาะจงกว่านี้ไม่ได้ การสร้างนอก sandbox สำเร็จแล้ว จึงไม่มีเหตุให้เปลี่ยน Dependency หรือระบบ Installer

## สถานะผลทดสอบก่อนการยืนยันล่าสุด

- ยังไม่ได้เปิด Installer เพื่อติดตั้งหรือถอนการติดตั้ง
- ยังไม่ได้เปิดใช้งาน UI เพื่อดูภาพจริงหรือทดสอบข้อความไทยบนจอ
- ยังไม่ได้ทดสอบเมาส์ แป้นพิมพ์ หรือจอสัมผัส
- ยังไม่ได้ทดสอบการปิดและเปิดแอปเพื่อยืนยัน Settings ที่บันทึกไว้
- ยังไม่ได้ทดสอบการเริ่ม Fullscreen, การสลับเข้า Guest, Escape และการกลับ Operator ด้วยการใช้งานจริง
- ไม่ได้ทดสอบ IPC ด้วยชุดทดสอบอัตโนมัติ
- ไม่ได้ทดสอบกล้อง ซึ่งอยู่นอกขอบเขต Milestone 1

# บันทึกเพิ่มเติม: แก้ปัญหาเปิดแอปหลังติดตั้ง

วันที่: 30 กันยายน 2026

## สาเหตุที่ยืนยันได้

`electron-squirrel-startup` อยู่ใน `dependencies` และ Main Process เดิมเรียกด้วย `require('electron-squirrel-startup')` แต่ `vite.main.config.mjs` กำหนดแพ็กเกจนี้เป็น External ส่วน `app.asar` ที่ Forge สร้างไม่มีโฟลเดอร์ `node_modules` จึงเหลือ `require` ที่ Node.js แก้ชื่อโมดูลไม่ได้ ข้อมูลนี้ตรวจจาก Main Bundle และรายการไฟล์ใน `app.asar` จริง ไม่ใช่การคาดเดาจากข้อความ Error เพียงอย่างเดียว

## การแก้ไข

- เปลี่ยน Main Process ให้จัดการอาร์กิวเมนต์ Squirrel ในตัว โดยยังคงสร้าง Shortcut เมื่อ `--squirrel-install`/`--squirrel-updated`, ลบ Shortcut เมื่อ `--squirrel-uninstall` และจบโปรเซสเมื่อ `--squirrel-obsolete`
- ปรับ `vite.main.config.mjs` ให้เหลือ `electron` เป็น External; ไม่พยายามโหลด `electron-squirrel-startup` ตอนรัน
- เพิ่มรุ่นแอปจาก `0.1.0` เป็น `0.1.1` เพื่อให้อัปเกรดการติดตั้ง `0.1.0` ที่มีอยู่ได้ โดยไม่ได้อัปเกรด Dependency
- ไม่เพิ่มฟีเจอร์อื่นและไม่เปลี่ยน Maker หรือระบบ Squirrel Installer

## ผลตรวจและทดสอบ

### ผ่าน

- `npm.cmd run typecheck` ผ่าน
- `npm.cmd run make` นอก sandbox ผ่าน และสร้าง Installer รุ่น `0.1.1`
- ติดตั้งผ่าน Installer ในโปรไฟล์ Windows นี้เพื่ออัปเกรดจาก `app-0.1.0` เป็น `app-0.1.1`; `RELEASES` ของการติดตั้งมี SHA-1 และขนาดตรงกับแพ็กเกจใหม่
- เปิด Main Process ผ่าน `Update.exe --processStart KOKOPhotobooth.exe`; พบโปรเซสจาก `app-0.1.1` และยังตอบสนองหลังเริ่ม 5 วินาที
- แยก `app.asar` ที่ติดตั้งจริงแล้วตรวจ Main Bundle: ไม่พบการเรียก `require('electron-squirrel-startup')` และพบตัวจัดการเหตุการณ์ Squirrel ทั้งสี่แบบ
- ปิดโปรเซสที่เริ่มเพื่อทดสอบแล้ว

### ไม่ผ่านหรือยังจำกัด

- `npm.cmd run make` ใน sandbox ยังล้มเหลวด้วย `TypeError: fetch failed` ระหว่าง `Copying files`; คำสั่งเดียวกันนอก sandbox สร้าง Installer ได้ จึงเป็นข้อจำกัดการดึงไฟล์เครือข่ายของ sandbox ไม่ใช่ข้อผิดพลาดการคอมไพล์ Main Bundle
- การเปิดทดสอบในสภาพแวดล้อมนี้ไม่มี `MainWindowHandle` ให้ตรวจ จึงยืนยันได้ว่า Main Process รุ่นใหม่เริ่มและไม่จบจากข้อผิดพลาดโหลดโมดูล แต่ยังยืนยันภาพหน้าจอหรือการโต้ตอบ UI ไม่ได้

### ยังไม่ได้ทดสอบ

- ยังไม่ได้ทดสอบการถอนการติดตั้งผ่าน Squirrel
- ยังไม่ได้ยืนยันด้วยภาพหน้าจอว่ามองเห็นหน้าต่าง Operator/Guest หรือภาษาไทยแสดงผลถูกต้องบนจอจริง

# บันทึกเพิ่มเติม: แก้หน้าต่างดำหลังติดตั้ง

วันที่: 30 กันยายน 2026

## สาเหตุที่ยืนยันได้

แพ็กเกจที่ติดตั้งรุ่น `0.1.1` มี `.vite/build/main.cjs` และ `.vite/build/preload.cjs` แต่ไม่มีไฟล์ Renderer ใน `app.asar` ขณะที่ Main Process เรียก `loadFile()` ไปยัง `.vite/renderer/main_window/index.html` สาเหตุคือ Vite ใช้ `root: 'src/renderer'` และปล่อยให้ `outDir` ของ Forge เป็นค่าเริ่มต้น ทำให้ HTML, JavaScript และ CSS ไปอยู่ที่ `src/renderer/.vite/renderer/main_window/` แทนตำแหน่งใน `app.asar` ที่ Main Process โหลดจริง หน้าต่างจึงเปิดขึ้นโดยไม่มีหน้า Renderer

## การแก้ไข

- กำหนด `build.outDir` ใน `vite.renderer.config.mjs` ให้ผลลัพธ์อยู่ที่ `.vite/renderer/main_window` จากรากโปรเจกต์ โดยยังคง `base: './'` สำหรับลิงก์ asset แบบ relative
- ซ่อน BrowserWindow ระหว่างเริ่มต้น และเรียก `show()` หลังเหตุการณ์ `ready-to-show` เพื่อไม่แสดงพื้นหน้าต่างก่อน Renderer พร้อม
- เพิ่มการบันทึก `did-fail-load`, การปฏิเสธ Promise จาก `loadFile()`/`loadURL()`, `did-finish-load`, `ready-to-show`, `preload-error`, ข้อความ Console ระดับ Error/Warning, `render-process-gone` และ `unhandledRejection` ลง `app.log` ในโฟลเดอร์ข้อมูลผู้ใช้ โดยไม่เปิด DevTools ใน production
- เพิ่มรุ่นแอปเป็น `0.1.4` สำหรับการอัปเดตผ่าน Squirrel; ไม่ได้อัปเกรด Dependency หรือเปลี่ยนระบบ Installer

- `npm.cmd run typecheck` ผ่านหลังแก้ Main Process ก่อนสร้างรุ่น `0.1.4`
- `npm.cmd run make` รุ่น `0.1.4` ผ่านนอก Sandbox รวมถึง Build ของ Main, Preload, Renderer และ Squirrel Installer
- ตรวจ `app.asar` ของ Build ล่าสุด พบ `.vite/renderer/main_window/index.html`, JavaScript, CSS และ `.vite/build/preload.cjs` ในตำแหน่งที่โค้ดอ้างถึง; HTML ใช้ asset path แบบ relative ที่ตรงกับไฟล์ที่แพ็ก
- ติดตั้ง/อัปเดตผ่าน Squirrel แล้ว พบโฟลเดอร์ `app-0.1.4` ในโปรไฟล์ Windows ทดสอบ
- `app.log` ของรุ่น `0.1.4` บันทึก `renderer-load-succeeded` และ `window-shown` หลังเริ่มแอป แสดงว่าโหลดหน้าเสร็จและ BrowserWindow เรียก `show()` แล้ว

### ไม่ผ่านหรือยังต้องติดตาม

- `app.log` รุ่น `0.1.4` บันทึก `renderer-load-rejected` ด้วยข้อความ `ERR_FAILED (-2) loading 'file:///.../app.asar/.vite/renderer/main_window/index.html'` ก่อนบันทึก `renderer-load-succeeded` และ `window-shown` ในการเริ่มครั้งเดียวกันตามลำดับเวลา สาเหตุเฉพาะของการปฏิเสธครั้งแรกยังระบุไม่ได้จากหลักฐานที่เก็บได้ การโหลดสำเร็จภายหลังยืนยันว่าไฟล์และเส้นทางใช้งานได้ แต่ควรเก็บบันทึกจากการเปิดครั้งถัดไปเพื่อตรวจว่าข้อผิดพลาดเกิดซ้ำหรือไม่
- `npm.cmd run make` ภายใน Sandbox ล้มเหลวระหว่าง `Copying files` ด้วย `TypeError: fetch failed`; การรันคำสั่งเดิมพร้อมสิทธิ์ดาวน์โหลดผ่านและสร้าง Installer ได้ จึงแยกได้ว่าเป็นข้อจำกัดการดาวน์โหลดใน Sandbox

### ยังไม่ได้ทดสอบ

- ยังไม่สามารถตรวจภาพหน้าต่าง Operator/Guest ด้วยสายตาหรือยืนยันการแสดงผลและการโต้ตอบ UI จริงได้ แม้บันทึกระบุว่าโหลดหน้าเสร็จและเรียก `show()` แล้ว เครื่องมือหน้าจอในสภาพแวดล้อมนี้ไม่แสดงหน้าต่าง KOKO Photobooth ในรายการแอป จึงห้ามถือว่าการแสดงผล UI ผ่าน
- ยังไม่ได้ทดสอบบนเครื่อง Windows เป้าหมายของงานจริง และยังไม่ได้ยืนยันว่าไม่มีหน้าต่าง Error หรือหน้า UI ว่างด้วยผู้ทดสอบ
- ยังไม่ได้ทดสอบกล้อง ซึ่งไม่อยู่ในขอบเขตงานนี้

# ผลยืนยันการทดสอบบน Windows ล่าสุด

ผู้ใช้รายงานและยืนยันด้วยตนเองว่าทดสอบโปรแกรมบนเครื่อง Windows แล้วผ่านครบทั้ง 9 รายการต่อไปนี้ ผลส่วนนี้เป็น **การทดสอบด้วยตนเองตามคำยืนยันของผู้ใช้** ไม่ใช่ผลจากชุดทดสอบอัตโนมัติ

1. เปิดโปรแกรมจาก Shortcut หรือ Start Menu — ผ่าน
2. ภาษาไทยแสดงผลถูกต้อง — ผ่าน
3. เปลี่ยนภาษาอังกฤษและกลับเป็นภาษาไทยได้ — ผ่าน
4. Settings ยังคงอยู่หลังปิดและเปิดโปรแกรมใหม่ — ผ่าน
5. Fullscreen และกด Escape เพื่อกลับสู่หน้าต่างควบคุม — ผ่าน
6. สลับหน้าภาพรวมและตั้งค่า — ผ่าน
7. ย่อ ขยาย และคืนขนาดหน้าต่าง — ผ่าน
8. เปิดโปรแกรมซ้ำโดยไม่มีหน้าต่างซ้อนหรือ Error ที่ไม่ควรเกิด — ผ่าน
9. ติดตั้งและถอนการติดตั้ง — ผ่าน

## ผลทดสอบอัตโนมัติและการตรวจสอบทางเทคนิค

- `npm.cmd run typecheck` ผ่าน ตามบันทึกการตรวจสอบก่อนหน้า
- `npm.cmd run make` สร้าง Build และ Squirrel Installer ได้เมื่อรันนอก sandbox ตามบันทึกก่อนหน้า; การรันใน sandbox เคยล้มเหลวด้วย `TypeError: fetch failed` ระหว่าง `Copying files`
- มีการตรวจเนื้อหาแพ็กเกจและไฟล์ Renderer ใน `app.asar` ตามบันทึกก่อนหน้า
- ไม่มีหลักฐานว่ามีชุดทดสอบอัตโนมัติสำหรับ UI, การเปลี่ยนภาษา, การคงค่า Settings, Fullscreen/Escape, การปรับขนาดหน้าต่าง หรือวงจรติดตั้ง/ถอนการติดตั้ง จึงไม่นับรายการเหล่านี้เป็นผลอัตโนมัติ
- `npm.cmd test` และ `npm.cmd run lint` ยังใช้ไม่ได้ เนื่องจากไม่มีสคริปต์ `test` และ `lint` ใน `package.json`
